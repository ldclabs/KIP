# 使用 KIP 2.0 实现参考 Brain

本指南是建立在协议之上的具象化默认策略，并非新增的核心类别（Core kind），也不是通用的认知算法。生产级实现为 [Anda Brain](https://github.com/ldclabs/anda-brain)，而非 `conformance/reference/` 下的小型模型。在将模型测试视作引擎实现或行为表现证据之前，请先阅读[实现证据](../conformance/Brain-Implementation-Evidence.md)。

## 默认记忆路径

1. 经认证的宿主捕获包含身份标识 / 摘要及规范任务 / 上下文作用域的不可变源数据。在存储敏感字节前应用准入与留存策略。持久化保存源序依赖与摄入确认回执。
2. 串行化处理相关的成型工作。优先记录精确陈述与显式纠错；无关的数据流可独立并行。始终以源顺序和生效时间为准，严禁将 Worker 完成时间作为“最新值”判定规则。Anda Brain 已具备共享的 Formation/Maintenance 准入关卡与顺序会话队列。
3. 在明确的短期预算内保留源材料。提取最小可用断言集，同时保留绑定了摘要的源定位符与抽取器版本。未决的行动者或 Schema 仅作为证据保留。低价值输入可通过显式决策直接跳过，无需凭空猜测数值分数。
4. 普通事实通常只需 Evidence、Proposition 与 Assertion。仅当情境分组确有助益时才添加 Event；仅当执行轨迹具有经验价值时才添加 Experience/Steps。Preference、Insight 与 SelfModel 属于可选的派生视图，绝非每条消息都必须复制的副本。必须保留必要的转换谱系。
5. 召回过程依次解析身份与作用域、枚举关键约束与 Commitment、校验 BELIEF 与先决条件，随后检索有界的经验与语义材料。每个通道均需记录执行计划。近似候选发现并不等同于语义完备。宿主在模型决策前必须保留强制性警告。
6. 若提取过程遗漏了潜在的决定性信息且源字节仍存留，应返回原始源数据或排队等待显式重新编码。只读召回绝不应暗中变更认知状态。未知或过期的外部事实可通过行动关卡生成验证请求；新鲜度属于谓词 / 上下文策略，而非置信度衰减。
7. 编码错误通过 recording_repair 修复。对于陈述的真实变更采用行动者替代（supersession），对于现实世界的变迁采用互补的生效区间（complementary valid intervals）。这些途径在根源、权限及历史解释上截然不同。
8. 任务恢复从限定作用域的 WorkingState 出发，结合全部增量页与当前基线校验进行。SDK 自动携带未完成的处理回执，在后发输入先完成时依然完整保留在先的未完成项。

Formation、Recall 与 Maintenance 可以使用单一模型、多个模型或确定性的宿主代码。协议修订不强制要求引入新的 LLM 流程。现有的 Anda Brain 服务已具备真实的供应商调用与原生 Nexus 接缝；可复用的评估应归入其外部 MIB 工作流。切勿仅为了证明满足本清单而在 Brain 内部另造一套庞杂的评估器。

## 低开销维护与单一权威记录

持久化显式强化与策略变更。针对可选的记忆惰性衰减（lazy mnemonic decay），`MnemonicState.memory_strength` 为最后显式写入的基数，`last_metabolized_at` 为其时间锚点，`strength_policy` 为锁定的策略工件（如声明的半衰期）。若缺少基数、锚点或策略，则保持未知状态；严禁凭空捏造 0.5。有效强度仅作为只读排序值进行计算。任何读取操作均不得回写新基数、推进版本号、递增使用计数或修改置信度。周期性整理（compaction）在确保等价的前提下可显式刷新锚点。不支持的策略必须显式报错。数值计算结果遵循可移植数值域规范。

在宣称节省开销之前，必须在相同策略与语料库下对比惰性模式与扫描模式。度量指标应包含空闲写入量、发出的信封数、缓存失效数、待处理积压量以及 p50/p95 召回开销。惰性模式避免的是常规的逐项衰减写入，而非必要的留存、纠错或租约维护工作。该能力通过 `lazy_mnemonic_strength` 进行对外声明。

保留版本、试验与评估指针及不可变记录。GradingState 的统计计数根据选定的经检验评估计算得出；若引擎缓存了计数，必须予以校验。DerivationState 仅表示复审进度；时效性来源于依赖校验。切勿创建另一套与之竞争的可变真实性标记。

Activity 与 DependencyBasis 构成依赖关系的权威来源。在同一次变更中生成或校验冗余谱系边，将语义先决条件与上下文 / 披露信息明确分开。兼容性视图可保留现有的 Facet / Structural 名称。测试通过丢弃物化视图并重新构建来验证；权威历史记录始终保持不变。

## 宿主易用性

五大 Memory Interface 意图依然是面向业务 Agent 的接口界面。使用导出的 `MemorySession` 辅助工具进行带作用域的未完成回执记账，并将其快照与宿主会话一同建立检查点。记录每项已确认的回执；只有切实处理了该回执的可信召回响应方可将其清除。回执溢出时需要有界排空或由宿主转存，绝不能直接丢弃较早的待处理回执。源数据捕获、稳定的幂等键生成及句柄授权均属于宿主的职责。该辅助工具不负责校验网络响应，也不赋予回执访问权限。

带作用域的 `ASSERT {context: :contexts}` 展开为现有的 context_refs 字段。针对旧版解析器和细粒度的 Evidence 角色，显式的 CREATE ASSERTION 依然可用。`context` 既不是 Evidence 的引用角色，也不是所有权授权。

时间戳解析通过 `parseTimestamp` 共享；宿主将非字符串错误映射为 TypeMismatch，将格式 / 日历错误映射为 ConstraintViolation。协议输入绝不进行静默修复。外部日期可在摄入时显式转换，并保留原始数据源及其精度与锚点。

## 评估顺序

优先运行真实的引擎与宿主可靠性测试。随后通过现有的 [BrainEvaluation](BrainEvaluation.md) 契约与 MIB 集成运行留出集（held-out）行为实验，锁定模型与工具版本、仅限训练集的记忆以及总体开销。明确区分提取召回率、候选召回率、回答正确性、过时回答、约束遗漏、弃权（abstention）、修复成功率以及可避免的重复错误。对比原始留存与压缩记忆的效果，并进行相关记忆消融实验。

ProcedureAssessment 可以在不引入新 Skill 状态的前提下确立某一准则下的适用性。只有经过授权的对比评估才能获得采纳地位（adopted standing）。机制通过、确定性模拟模型测试以及准确的源数据检索本身，绝不能当作真实模型的学习收益来汇报。不可用的模型供应商 / 数据集或不受支持的 MIB 条件，应保持显式的未执行关卡状态。
