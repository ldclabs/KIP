# 大脑评估与发布门禁 (Brain Evaluation and Release Gates)

**[English](./BrainEvaluation.md) | [中文](./BrainEvaluation_CN.md)**

**参考评估工作流；报告完整性对于学习主张具有规范约束力。**

协议一致性、可靠执行与行为改进属于相互独立的门禁。通过其中一项绝不能替代另一项。本代码库修订版本不提供任何实证结果；所附带的报告模板显式标注为 `not_run`。

## 1. 协议与制品门禁 (Protocol and artifact gate)

运行英文语言/契约测试、制品摘要验证、有限模型以及适用的引擎适配器向量。记录引擎/版本、包与模式摘要、所支持的能力、测试套件版本及实际覆盖范围。不支持的必需能力、纯模型结果、跳过的检查项及适配器错误必须保持可见。仅运行部分向量的测试器不能宣告整个 Profile 通过（PASS）。

## 2. 可靠运行时门禁 (Reliable-runtime gate)

使用隔离的测试 Space 与受控的外部执行器。在以下关键点注入进程/网络故障：意图已提交、分发前、产生效果后、Outcome 提交前、租约接管、Watch 重新设防、数据流重放/截断、信任/授权更新、根证据纠错以及并发缓存更新。验证：

- 相同尝试得到调和，不存在未经确认的重复外部效果；
- 替代工作进程恢复执行，旧防护令牌无法写入/分发；
- 在完整覆盖授权截止时间之前，不会产生虚假的静默触发；
- 不存在陈旧的已采纳派生，亦无跨上下文/跨授权的缓存复用；
- 遗忘擦除涵盖语义副本、重放输入以及受控备份；
- 在持续输入负载下，内存、积压任务、重放成本及 p50/p95 延迟保持有界。

在运行前指定各项限额与告警/恢复准则。严禁将发送真实外部消息或执行不可逆操作作为基准测试的副作用。

## 3. 行为学习门禁 (Behavioral-learning gate)

保持业务模型/版本、任务环境、工具策略及总预算恒定。在重复随机种子与配对任务下对比以下实验条件：

```text
no persistent memory                         无持久记忆
retained source records / ordinary vector retrieval 保留源记录 / 普通向量检索
semantic KIP memory                          语义 KIP 记忆
semantic + Experience                        语义 + 经验
semantic + Experience + immutable Skill revisions 语义 + 经验 + 不可变技能修订版本
relevant memory ablated                      相关记忆消融 (ablated)
irrelevant/shuffled memory control           无关/打乱记忆对照组
```

将编码、维护、检索、工具及评估成本全部计入预算；不能将隐藏的大规模巩固预算伪装为等成本对比。仅允许从训练交互中创建记忆。在学习前冻结评估保留集 (holdout)，并在准入、检索及编译中排除测试标签/测试结果。独立仪器化系统测量执行策略；模型自身的陈述绝非客观真值。固定观察者配置以及所有权/控制权假设。

独立测量以下能力：

| 能力 | 测试方法 | 旨在捕获的失效模式 |
| --- | --- | --- |
| 留存与更新 | 跨会话事实、显式纠错与精确时间边界 | 陈旧答案或凭空捏造的确定性 |
| 隐式约束 | 后续任务未显式要求先前的约束 | top-k 丢失重要偏好/义务 |
| 程序迁移 | 具有新表层形式的相关保留集任务 | 将死记硬背的轨迹误认为可复用技能 |
| 适用性 | 变更工具/环境/先决条件 | 来自已采纳流程的负迁移 |
| 故障规避 | 先前观测到的失败与反例 | 重复犯下可避免的错误 |
| 因果效用 | 相关消融对照配对全记忆条件 | 将检索暴露度误认为能力改进 |
| 选择性 | 原始保留对比纯压缩、重新编码及省略细节 | 未经测量的信噪比/信息损失 |
| 前瞻记忆 | 伴随重启的到期/匹配/不匹配场景 | 遗漏义务或虚假打扰 |
| 遗忘擦除 | 范围删除后的召回/重新导出/重放 | 已删除字节仍作为语义记忆存活 |

公开基准版本可作为补充测试集，绝不能代表整个门禁。LongMemEval 针对长期交互召回、时序推理、更新与弃权 (abstention)；LoCoMo-Plus 强调潜在隐式约束；LongMemEval-V2 增加了环境状态、工作流、陷阱与前提感知。固定确切的数据集/制品版本并审查任务/标签质量，绝不能假定基准名称本身能证明覆盖度。参考来源：[LongMemEval](https://arxiv.org/abs/2410.10813), [LoCoMo-Plus](https://aclanthology.org/2026.acl-long.1150/), [LongMemEval-V2](https://arxiv.org/abs/2605.12493)。

## 4. 统计与成本报告 (Statistical and cost reporting)

预先声明对比指标、实际改进裕度 (practical improvement margin)、置信区间方法、重复次数、分层/配对、缺失性及停止规则。按上下文汇报结果以及汇总数据；变更任务组合不能确立能力改进。报告不确定性、失败/中止/未知的尝试及负迁移，而非仅报告成功案例。在可行时优先采用受控干预；观察性对比必须声明其残留混杂因素，且不能声称实现了随机化。

仅当保留集改进满足所声明的实际效益与不确定性要求、且未违反安全/负迁移或预算限制时，学习门禁方可通过。结果可以保持为建议性/不充分 (advisory/insufficient)。失败应当驱动创建新的不可变技能修订版本并开启全新试验，绝不能通过重写基准或篡改旧裁决来应对。

## 5. 报告契约与可复现性 (Report contract and reproducibility)

遵循 `../schemas/kip-brain-evaluation.schema.json` 以及模板 `../conformance/fixtures/brain-evaluation-not-run.json`。在 Governance 治理下妥善保存模型/工具版本、语料库与观察者摘要、条件定义、随机种子、预算、独立尝试计数、指标/置信区间以及追踪制品引用。

`not_run` 要求无测量得分且已完成运行次数为零。`completed` 要求有实际运行与测量；它仅代表实验完成，不代表学习门禁已通过。每一项公开发布的学习主张均必须链接该报告及其预先声明的准则。被擦除/扣留的追踪记录会降低可复现性，必须如实汇报。

## 6. 接口成本对比实验 (Interface-cost experiment)

在**相同**的 Nexus、输入语料库、记忆策略、业务模型及工具权限下，对比直接使用 KQL/KML/META 与使用可选记忆接口（Memory Interface）的表现。两种测试条件必须保持完全一致的可观测源、范围、信念、修订与擦除语义。通过省略证据/覆盖检查而换取的表面开销节省属于无效评估。必须将适配器/模型工作、摄入、后台处理、检索、重试以及证据展开全部计入总预算中，包括对调用方隐藏的工作。

采用配对场景：新事实；现实变更与事实纠错的对比；仅限单次任务的指令；未解析行动者/Schema 源的召回；未完成任务的恢复上下文；反馈；以及限定范围的遗忘。测试场景应包含延迟/乱序形成、权限变更、结果句柄过期、输出受限和网络重试。在两种测试条件中使用相同的保留源，并确定性地控制后台工作进程延迟。

衡量首发语义正确率、业务智能体调用次数、内部 KIP 调用次数、固定分词器下的总输入/输出 Token 数量、p50/p95 延迟、恢复成功率、挂起处理持续时间以及不支持的自动操作发生率。记录每种测试条件所加载的速查卡和指令/分词器版本。切勿从速查卡行数或可见调用次数更少就推断成本更低。报告带有不确定性的实测差异；本代码仓库仅提供实验契约，不提供具体实测结果。
